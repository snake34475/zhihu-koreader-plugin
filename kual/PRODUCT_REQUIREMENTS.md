# 知乎 Kindle 独立阅读器：UI 产品需求与设计委托

> 请以此文档为依据，为 Kindle Paperwhite 4 设计一款由 KUAL 启动的**独立知乎阅读程序**。先交付可在 Mac 浏览器中点击预览的黑白界面原型，再交付可供原生程序实现的页面规格。浏览器原型用于快速评审；Kindle 端不预设运行网页。

## 1. 产品定位

面向用户在地铁等离线或弱网场景中的个人阅读：浏览知乎热榜、推荐和问题下的回答；在有权限且接口可用时阅读回答正文、评论及回复；断网时继续阅读已缓存内容。产品以文字、清晰导航和可靠状态反馈为核心。

目标平台是 **Kindle Paperwhite 4，竖屏可见区域 1072 × 1448 像素，灰阶墨水屏，触摸操作**。该尺寸由设备显示模式读取；设计稿请提供此尺寸的实际画布，并考虑较小物理屏幕上的可读性。KUAL 仅负责启动程序，阅读界面由新的独立程序实现。

审美方向可参考用户设备上 KUAL 版微信读书的清爽阅读感；评论的信息层级参考知乎原版。请形成自己的黑白排版体系，不照搬手机 App 的密集布局。

### 设计目标

1. 从 KUAL 启动后尽快出现可读内容；优先显示最近缓存，再由用户主动刷新。
2. 一眼区分“回答摘要”“已取得正文”“缓存内容”和“获取失败”；**不把未经证实的正文标为完整回答**。
3. 从列表进入回答、评论、子评论后，返回时保留原来的列表位置和分页。
4. 控件适合手指触摸；作者、正文、回复对象、层级和操作入口容易分辨。
5. 支持字体大小、行距、前光亮度、暗黑模式、墨水屏刷新策略、账号状态与退出登录。这些是独立版的新需求，不应误认为现有插件已经全部实现。

## 2. 现有 KOReader 原型：功能基线

以下来自当前代码与项目记录，供设计师理解已有内容和操作。**“已有代码”不等于独立 KUAL 版已经实现，也不等于所有操作均已完成 Kindle 实机验收。**

代码核对点为提交 `26e62c2`；评论层级改动已部署到 Kindle，但仍需在 KOReader 重启后验收实际显示和触摸行为。

| 能力 | 现状 | 设计时的处理 |
|---|---|---|
| 热榜 | 网页会话读取，最多 30 条；可手动刷新，启动优先显示最近缓存 | 首页主频道 |
| 推荐 | 单独频道，上一批/下一批、刷新；依赖有效会话 | 与热榜并列，不冒充知乎官方 App 的完整个性化首页 |
| 问题与回答 | 问题摘要、问题下回答摘要列表，按批翻页 | 明确“摘要”标记；回答列表可继续进入阅读页 |
| 回答正文 | 对单条回答按需请求；已取得且通过现有校验的正文可缓存、刷新，阅读页左右切换相邻回答 | 显示“已取得正文/仅摘要/付费或受限”等状态；不宣称任意回答都能取全文 |
| 评论与回复 | 一级评论分页；根评论返回的子评论最多先展示两条；更多回复进入独立分页页；有评论缓存 | 作者与正文分行、子回复缩进、显示“回复某人”，超过两条显示“查看全部回复” |
| 知乎直答 | 输入问题、选择模型、阅读生成结果；使用独立的开放平台密钥 | 独立频道，视觉上与知乎原站回答区分 |
| 离线阅读 | 最近热榜、推荐、问题回答摘要、直答及已取得的正文/评论缓存 | 显示缓存时间、可读范围和离线状态 |
| 登录 | 可导入用户浏览器会话，可选保持登录、会话校验、退出登录；设备直接扫码遇到人机验证，尚未打通 | P0 设计“账号状态/导入说明/失效提示/退出”；扫码登录只做明确标注的候选方案 |
| 原始链接 | 复制链接；Kindle 无通用浏览器时显示二维码供手机打开 | 阅读页的次级操作 |
| 图片 | 当前只读文字，不下载正文图片 | 用简洁的“图片未加载”占位；不要以图片信息流为默认方案 |
| 显示与刷新 | 当前设置页可触发 KOReader 夜间模式；正文页会请求整页重绘。插件没有自己的亮度、字体和墨水屏刷新策略设置 | KUAL 独立版需设计并实现独立设置；区分联网更新内容与屏幕全刷 |

当前 KOReader 版本的页面包括：热榜首页/空状态、推荐列表、问题详情与回答摘要列表、摘要阅读页、已登录正文阅读页、一级评论页、子评论页、直答输入与结果、离线菜单、设置与账号、条目操作弹窗、二维码/加载/错误提示。KUAL 独立版可以重新组织这些页面，不必照搬 KOReader 的菜单样式。

## 3. KUAL 独立版的信息架构

```text
KUAL 启动知乎
  └─ 首页：热榜 / 推荐 / 离线 / 直答
       ├─ 问题详情 → 回答列表 → 回答阅读 → 评论 → 子评论弹窗
       ├─ 回答条目 ─────────→ 回答阅读 → 评论 → 子评论弹窗
       ├─ 直答输入 → 直答结果
       └─ 设置与账号 → 字体/亮度/暗黑模式/屏幕刷新、会话导入/退出
```

### P0 页面与交互

1. **热榜首页**：顶部产品名、频道切换与账号状态；卡片展示序号、类型、标题、作者（如有）、两到三行摘要；显式刷新、缓存时间、加载/空/断网状态。点击问题进入回答列表，点击回答进入阅读页。
2. **推荐列表**：沿用列表卡片组件；显示“上一批/下一批”和刷新，保留批次位置。加载下一批时当前内容继续可见。
3. **问题与回答列表**：问题标题及摘要固定在页面上部；回答条目展示作者、摘要和“仅摘要/正文已缓存”状态；按批翻页。
4. **回答阅读页**：标题、作者、来源与取得时间；正文/摘要状态明显但不抢占阅读空间。正文支持上下阅读、左右切换上一条/下一条；底部固定提供“评论”“摘要/正文切换”“刷新正文”，返回时保留列表位置。正文不可用、付费或仍被截断时展示实际原因并保留摘要。
5. **评论页**：根评论的作者独占一行，正文另起一行；默认展示接口提供的前两条子回复。子回复视觉缩进，清楚表达“甲 回复 乙”；回复总数超过预览时显示“查看全部 N 条回复”。一级评论有下一页/刷新/返回回答。
6. **子评论弹窗或独立层**：保留父评论上下文；分页展示回复，支持返回评论页和刷新。关闭后恢复原评论位置。请给出适合墨水屏的弹窗与全屏页两种方案，并推荐其一。
7. **离线页**：按热榜、推荐、回答、直答等类型组织最近缓存；每项展示取得时间及“仅摘要/已取得正文”等范围。无缓存时给出清晰引导。
8. **直答页**：问题输入、模型选择、提交与结果阅读；标明这是“知乎直答生成内容”，与用户回答区分。
9. **设置与账号页**：分为“阅读显示”“屏幕刷新”“账号与接口”三组。包含字体大小、行距、前光亮度、暗黑模式、屏幕全刷策略、登录状态、浏览器会话导入说明、保持登录和退出登录。开放平台 Access Secret 与知乎网页会话分区，避免混淆。

### 阅读显示与刷新：请单独设计这些控件

| 设置/操作 | 交互要求 | 放置位置 |
|---|---|---|
| 字体大小 | 提供明确的增大/减小操作和当前级别；调节后立即预览，尽量保留原阅读位置 | 阅读页快捷设置 + 设置页 |
| 行距 | 至少提供紧凑、标准、宽松三个档位；变化后立即预览，持久保存 | 阅读页快捷设置 + 设置页 |
| 前光亮度 | 提供大按钮的减/增和当前亮度；支持关灯。应用记住自己的亮度，退出后恢复启动前的系统亮度。设备不支持或驱动不可用时显示原因，不出现无效滑块 | 阅读页快捷设置 + 设置页 |
| 暗黑模式 | 明确的开/关状态；正文、列表、评论、弹窗与设置页一起切换；切换时整屏重绘并保留阅读位置，重启后保留选择 | 阅读页快捷设置 + 设置页 |
| 屏幕刷新策略 | 提供“自动（推荐）”“每次翻页全刷”“减少闪烁”三个易懂选项；实际全刷频率需在 PW4 实测后确定，暂不在稿中承诺具体次数 | 设置页 |
| 立即全屏刷新 | 清除残影，只重绘屏幕，不请求知乎、也不改变缓存和阅读位置；操作后给出短暂反馈 | 阅读页快捷设置；其他页面可从设置页触发 |
| 联网刷新内容 | 热榜、推荐、回答正文、评论各自有明确刷新入口；成功后更新对应缓存，失败时保留当前内容与位置 | 各内容页面 |

**两个“刷新”必须用文字区分**：“刷新内容”会发网络请求；“全屏刷新/清除残影”只重绘墨水屏。请设计两个不同的入口及反馈，不使用同一个含义模糊的刷新图标。阅读页快捷设置应能一两次触摸到达，关闭后返回原阅读位置。前光与刷新策略的最终控制能力以 PW4 实机适配为准。

### 通用状态与弹层

- 首次使用、未登录、会话过期、断网、请求中可取消、空列表、接口拒绝、人机验证、付费/无权访问、正文可能截断、缓存可用但过期、下一页加载失败。
- 长按条目的操作菜单：阅读摘要、尝试获取正文、查看评论、复制/用手机打开原始链接。
- 请求失败时优先留在当前页面；如有缓存，明确提示“正在显示缓存”。

## 4. 墨水屏设计约束

- 以黑、白及有限灰阶工作；不用颜色作为唯一状态提示。避免动画、渐变、大面积连续反色和频繁局部重绘。
- 清楚区分标题、作者、摘要、正文、评论和次级说明；提供适合中文长文的行长、行距与段间距。
- 底部操作必须始终可见且可点击。触控目标要有足够面积，不依赖细小链接或复杂手势才能完成主要任务。
- 列表、阅读、评论均需给出刷新后的整屏状态；翻页和弹层关闭时避免留下残影。Mac 原型可模拟加载与闪屏，但实际刷新效果以 Kindle 验收为准。
- 启动页不要使用耗时动画；优先直接呈现缓存。需要设计浅色与暗黑两套关键页面，并展示亮度/字体快捷设置与“清除残影”的位置。

## 5. 请设计 AI 交付

1. 一张信息架构图和三条用户路径：热榜→正文→评论→回复；问题→回答摘要→正文；断网→离线阅读。
2. 上述 **9 个 P0 页面**的 1072 × 1448 灰阶高保真稿，以及登录失效、仅摘要、正文受限、空状态和断网缓存状态。设置页及阅读页快捷设置需覆盖亮度、字体、行距、暗黑模式和屏幕刷新。
3. 可在 Mac 浏览器打开、使用假数据点击跳转的 HTML/CSS/JS 原型。不得放入真实 Cookie、密钥、回答正文或个人数据。原型的布局规格应能转写为原生程序，不依赖 Kindle 运行浏览器。
4. 组件规范：列表卡片、标题栏、底部操作栏、状态标签、评论层级、弹窗、按钮；给出尺寸、间距、字体等级、灰阶值和触控范围。
5. 对首页与阅读页各提供两个明显不同的视觉方向，说明哪一个更适合快速启动与长时间阅读；最终推荐一套。请用真实中文长度的**虚构示例文本**检验长标题、长回答和多层回复的排版。

## 6. 本轮设计边界

当前不设计搜索、点赞、发评论、关注、私信、视频播放、图片瀑布流、收藏夹同步或自动批量抓取。扫码登录、人机验证处理与任意回答全文获取均不能在设计稿中表现为已稳定可用的能力。未来如扩展其他内容平台，应能复用列表、阅读、评论组件，但本轮只设计知乎。
