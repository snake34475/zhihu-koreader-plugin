## 换一台电脑怎么继续

```bash
git clone git@github.com:snake34475/zhihu-koreader-plugin.git
cd zhihu-koreader-plugin
open kual/prototype/index.html      # 原型：不需要服务器，不需要联网
```

- 设计稿在 Ardot 云端，需要**同一个账号**才有权限；没有权限时，本文档的屏幕清单与规格表仍然够用，原型也能完整走查。
- 原型是纯静态文件，`file://` 直接打开即可；要放到局域网给别的机器看，在 `kual/prototype/` 里跑 `python3 -m http.server 8000`。
- KUAL 只负责启动；独立版需要自己的界面、设备适配和会话管理。现有 `zhihu.koplugin` 继续在 `main` 分支维护，不能直接当作 KUAL 程序运行。

## 原型怎么用

打开 `prototype/index.html`：右侧是 1072 × 1448 的设备画面（按窗口等比缩放），左侧是**评审台**——它只是评审工具，不属于设计稿。

评审台可切换：断网（隧道内）、模拟墨水屏闪屏、暗黑模式、首次使用（无缓存），并提供任意一屏的直达按钮与「全屏刷新（清残影）」「重置原型」。

### 可点的路径

- **热榜 → 问题 → 回答 → 评论 → 子回复 → 逐级返回**：返回时列表停在原位置（滚动位置逐视图记忆）
- **断网 → 刷新内容**：页面顶部出现「网络不可用，正在显示 20:41 的缓存」，内容与位置都保留；离线频道按类型分组，每项标「仅摘要 / 正文已缓存」
- **阅读页 → Aa**：字号 5 档、行距 3 档、前光档位、暗黑、清除残影；调字号时阅读位置保持
- **长按列表条目**：阅读摘要 / 尝试获取正文 / 查看评论 / 复制原始链接
- **推荐频道**：上一批 / 下一批，翻批后批次位置保留

### 直达某一屏（地址栏 hash）

`#reading`、`#comments`、`#replies`、`#offline`、`#settings`、`#login`、`#empty`、`#menu`、`#sheet`、`#limited`、`#excerpt`、`#result`、`#direct`、`#recommend`、`#question`、`#hot`
加 `-dark` 为暗黑版（如 `#reading-dark`）；加 `?solo=1` 隐藏评审台、按 1:1 渲染，适合截图。

### 原型与设计稿的差异（有意为之）

| 点 | 设计稿 | 原型 |
|---|---|---|
| 阅读翻页 | 整屏分页 | 连续滚动（浏览器行为，真机按分页实现） |
| 前光亮度 | 有档位控件 | 只显示数值，Mac 无法驱动 Kindle 前光 |
| 暗黑主按钮 | 仅在 20 / 21 两屏体现 | 主按钮与分段选中改为描边，避免黑底白块 |
| 推荐批次 | 06 屏有上一批 / 下一批 | 补充了批次条与翻批行为 |
| 二维码 | 阅读页次级操作 | 只提示「可生成二维码用手机打开」，未画码 |

## 规格 token（原生实现直接照抄）

单位 px，画布 1072 × 1448。

| 项 | 值 |
|---|---|
| 页边距 / 正文行长 | 64 / 944（约 26 字） |
| 标题栏 / 频道栏 / 缓存条 / 底部操作栏 | 140 / 128 / 96 / 132 |
| 触控最小尺寸 | 88 × 88；主按钮 112 高，次按钮 80 高，列表整行可点（≥ 200） |
| 字阶 | H1 48/64 Bold ｜ H2 44/62 SemiBold ｜ H3 40/56 SemiBold ｜ 正文 38/68 ｜ 摘要 32/52 ｜ 评论 34/58 ｜ 元信息 24–26/40 |
| 灰阶 | `#000000` 主 ｜ `#3C3C3C` 摘要 ｜ `#6E6E6E` 元信息 ｜ `#9A9A9A` 占位 ｜ `#C8C8C8` 细线 ｜ `#EFEFEF` 浅底 ｜ `#FFFFFF` 纸白 |
| 暗黑映射 | 底 `#000000` ｜ 正文 `#EDEDED` ｜ 元信息 `#9E9E9E` ｜ 细线 `#3A3A3A` ｜ 浅底 `#141414` |
| 圆角 / 效果 | 仅 0 / 8 / 10 / 12；无投影、无渐变、无动画装饰 |
| 字体 | Noto Sans SC（数字与编号用 Inter） |

两个「刷新」必须分开，不可共用一个图标：

- **刷新内容 / 刷新正文** —— 发网络请求，失败保留当前内容与位置
- **清除残影 · 全屏刷新** —— 只重绘屏幕，不联网、不改缓存与阅读位置

## 关键决策

- 视觉方向采用 **A 版式驱动**（留白 + 细线分区），未采用 B 卡片流：A 一屏多约 15% 可读文字，重绘面积小、残影轻；详见 04 屏。
- 频道选中态用 **字重 + 灰度**，不用下划线或色块（黑块在局部刷新下容易留残影）。
- 子回复以**全屏页**为主推，弹窗仅作备选：944 宽的弹窗里三层回复只剩约 30 字/行，且关闭残影难处理。
- 登录不画扫码：PW4 上直接扫码会被人机验证拦截（302 `verification_required`），只提供「导入浏览器会话」与「继续离线阅读」。
- 正文受限时展示具体原因，摘要不冒充正文。
