# 知乎 KOReader 插件 · 0.2.6

面向 Kindle 墨水屏的只读客户端。搜索入口、请求、设置项与搜索缓存类别均已移除；知乎直答继续使用开放平台。热榜、问题回答列表和个性化推荐现已改用知乎网页端接口。0.2.5 增加可选的“保持登录”：开启后 Cookie 保存在 KOReader 设置目录的权限 0600 文件，并在恢复前校验 `/api/v4/me`。0.2.6 将回答阅读页操作栏固定在底部并强制整页刷新，删除重复的侧边上一条/下一条与翻转按钮；回答间通过左右滑动切换。设备端扫码仍可能遇到人机验证，也可从电脑临时导入浏览器会话。

列表端点探针运行方式：在仓库的 `tools/` 目录运行 `py .\zhihu_feed_probe.py`。脚本会隐藏读取浏览器 Cookie，并通过现有 SSH 工具在 PW4 内存中验证热榜、推荐、问题回答三个候选端点；结果只包含状态、条数、字段形状和分页标记。插件现将网页列表缓存保存到独立文件，不与旧开放平台列表缓存混用。

## 当前功能

- 在文件管理器和阅读器的“工具”菜单注册“知乎”。
- 点击“知乎”直接进入内容首页，优先显示最近网页热榜缓存；顶部提供热榜、推荐、直答、刷新、离线和设置。没有缓存时显示首次使用提示，不会自动联网。
- 热榜、推荐和问题回答列表使用网页登录会话。推荐及问题回答列表按知乎返回的同端点分页 URL 继续读取；问题回答每批最多 10 条，本批内部使用 KOReader 原生列表分页。
- 问题的回答摘要列表保持不变；轻点回答会优先读取独立正文缓存，缓存未命中时再按需请求已登录正文。正文页支持左右滑动切换回答，并可打开评论、查看摘要或刷新正文；打开一条正文后只尝试预缓存当前列表中的下一条回答，预取可取消。长按操作仍可用，但阅读不依赖长按。热榜中的回答也可轻点读取正文。评论页优先使用本地分页缓存，可继续翻页或刷新当前页。
- 列表页与阅读页标题栏显示当前时间，每分钟自动刷新。
- “设置”提供夜间模式开关，联动 KOReader 全局反色，适用于本插件页面。
- 设置中可主动发起知乎扫码登录或导入电脑一次性探针传来的浏览器会话。导入交接文件在 PW4 `/tmp` 临时保留 10 分钟，点击导入后立即删除，并通过 `/api/v4/me` 校验。默认不持久保存 Cookie；开启“保持登录”后，Cookie 白名单写入单独的 `settings/zhihu_session.json`，文件权限为 0600。退出插件或 KOReader 后会话可在下次使用时恢复并重新验证；关闭保持登录或退出知乎登录会删除文件。人机验证会停止流程，不会自动解题。
- Cookie 导入步骤：先在电脑浏览器登录知乎，然后从浏览器开发者工具的 Network 请求（例如 `/api/v4/me`）里复制 Request Headers 的 `Cookie` 值；在项目目录运行 `python3 tools/zhihu_cookie_import.py`，按隐藏输入提示粘贴完整单行 Cookie。脚本会筛选必要 Cookie、通过 SSH 发送到 Kindle 并校验账号，只在校验成功后写入 10 分钟临时文件。回到 KOReader 的“知乎 → 设置”，点击“导入电脑临时传入的浏览器会话”；再开启“保持登录”。不要把 Cookie 粘贴到聊天、命令参数或文件中。
- 回答阅读页底部及回答行长按菜单提供“获取正文”和“查看评论”。每次只读取一条回答或一页评论，用户可取消；正文需匹配回答 ID、非空并通过付费/截断检查后才标记为已校验。评论逐页读取服务端游标并显示取得时间和本页条数。
- 已登录内容写入独立的 `zhihu-session-cache/`，只保存通过检查的正文和评论，不写入 Cookie。会话失效、挑战、受限内容或网络错误时保留摘要；已有通过检查的内容可离线重读。
- 仍保留“匿名尝试获取正文”作为单次诊断入口，不需要 Access Secret，不自动重试，也不批量抓取。
- 最近一个问题保留最近读过的 10 批回答摘要，离线菜单可打开最近一批。刷新失败保留旧内容，重复阅读缓存不请求网络。
- 设置 HTTPS Base URL、Access Secret、热榜数量 1～30、超时 5～120 秒及直答模型。
- 密钥输入默认隐藏，可显示/隐藏或清除；设置列表不展示密钥。
- 热榜列表点击阅读标题、摘要、作者、原始时间字段及来源链接。
- 长按结果可阅读、打开/复制原始链接或再次缓存这次结果。
- 直答使用非流式文本阅读器，保留段落并转换基本 Markdown/HTML。
- 成功请求自动保存最近一份热榜和直答；失败不覆盖旧缓存。
- “离线缓存”无需网络。相同查询请求失败时自动打开旧缓存，其他查询的缓存由用户自行打开。
- 加载提示、轻触取消、请求超时、鉴权/额度/网络/格式错误提示；不自动重试。

图片下载、收藏、HTML/EPUB 导出及 WebBrowser 联动尚未实现。图片设置目前固定为关闭。搜索已从当前产品范围移除。

## 原始链接与阅读边界

平台返回的摘要不代表完整原文。按需探测使用未公开的 `GET https://www.zhihu.com/api/v4/answers/{id}?include=content,excerpt,paid_info`，只接受 HTTP 200、匹配回答 ID、非空正文且未检测到付费或截断提示的响应。网页接口没有独立的“全文完整”标记，因此显示为“回答正文”，不保证已得到所有文字或媒体。探测不会自动弹出或绕过人机验证；失败不覆盖摘要或离线缓存。

2026-11-02 在用户 PW4 上对一条公开回答实测：网页详情、移动端详情和原始页面均返回 HTTP 403；本插件的探测将网页详情识别为人机验证，提取字数为 0。2026-11-03 新版隔离探针在 PW4 的登录页返回 HTTP 302 `verification_required`，因此没有请求二维码、正文或评论。二维码登录路线按计划停止；电脑隐藏输入 Cookie 的临时导入路线已部署到 PW4，仍待重启和实机交互验收。

`question_answers` 只返回回答摘要或截取文本。已登录阅读使用知乎网页端回答详情和评论端点；不保证知乎会允许当前设备登录。2026-11-03 用户在 PW4 上手动提供 Cookie 的一次探针，回答详情与评论前两页均返回 HTTP 200；评论仍有后续游标，正文接口没有可靠的全文标记。该结果是初步设备证据，不构成所有回答完整或正式 UI 已验收的承诺。扫码成功提示前必须校验 `/api/v4/me`；登录页挑战、人机验证及设备实测失败均按停止状态处理。

设备支持 `Device:openLink()` 时使用系统打开链接。Kindle 的 KOReader 通常没有通用网页打开能力，此时显示二维码供其他设备访问；也可复制链接。直接在 Kindle 内阅读原始网页需要后续 P1 的 WebBrowser 联动。

## 数据位置

| 数据 | 路径（相对 KOReader 数据目录） |
| --- | --- |
| 配置 | `settings/zhihu_configuration.json` |
| 最近热榜 | `zhihu-cache/hot.json` |
| 最近直答 | `zhihu-cache/answer.json` |
| 最近问题的回答批次 | `zhihu-cache/question.json` |
| 网页热榜、推荐与问题回答摘要 | `zhihu-cache/web-hot.json`、`web-recommend.json`、`web-question.json` |
| 已校验的登录正文与评论页 | `zhihu-session-cache/` |
| 可选的保持登录会话 | `settings/zhihu_session.json`（明文 Cookie，权限 0600） |

配置通过插件设置页保存，不会自动读取示例 Lua 文件。Access Secret 以明文保存在独立配置文件中，应按密码保护；卸载插件不会删除它。清除密钥会重写配置，不保留旧配置备份。

缓存保存版本、查询、时间及经过脱敏的 API JSON。凭证字段和响应中意外回显的当前密钥会被清理，JSON null 哨兵会被省略。每类只保留最近一次；旧缓存不会因时间过期而删除，阅读时显示缓存时间。缓存可能含个人查询和回答，请自行保护备份。

日志只写数字 HTTP 状态码和耗时，不记录请求头、查询、密钥、响应正文或异常原文。禁止自动跟随 API 重定向。响应上限 1 MiB，缓存文件读取上限 4 MiB。

网络使用 KOReader 自带 LuaSocket/LuaSec，在 `Trapper` 子进程执行；套接字与接收过程受超时限制，UI 还会在超时后取消子进程，以覆盖 DNS 解析等套接字超时之外的等待。取消后的请求可能已被服务端执行，插件不会自动再次发送。

## 安装与回退

目标是 Paperwhite 4 和 KOReader 2026.07.x。已在用户 PW4 上使用原生 LuaJIT、JSON 库和真实控件生成并检查三张离屏预览；这不等于真实网络、触屏操作和持续使用验收。

1. 先确认设备实际 KOReader 安装目录和数据目录；如已装过此插件，在插件目录之外备份旧目录与上述数据。
2. 将整个 `zhihu.koplugin` 目录复制到设备的 `koreader/plugins/` 下，保持 `plugins/zhihu.koplugin/main.lua` 这一层级。
3. 重启 KOReader，进入“工具 → 知乎 → 设置”，直接在设备上填写密钥。不要把真实密钥放进 SSH 命令、聊天或 Git。
4. 设置页导入电脑临时传入的浏览器会话；如需跨重启保持登录，点“保持登录：关闭”开启后再验证热榜、推荐、问题回答分页、直答和断网缓存。开启时 Cookie 会以明文保存在设置目录，文件权限为 0600。
5. 回退时移除 `plugins/zhihu.koplugin/` 并重启。配置和缓存独立保留；需要清除时单独删除上表中的文件。

设备插件目录已确认是 `/mnt/us/koreader/plugins/zhihu.koplugin`。更新仅替换插件目录，配置、`settings/zhihu_session.json` 和缓存均在插件目录外，不会被普通插件更新覆盖；卸载 KOReader 数据目录、重置设置或手动删除对应文件仍会清除它们。旧插件备份在 `/mnt/us/koreader/backups/`。安装后需重启 KOReader 才会加载新代码。

## 离线测试

在项目根目录运行：

```sh
python3 -m pip install lupa
python3 zhihu.koplugin/tests/run.py
```

也可用 `--deps <目录>` 指定已安装 `lupa` 的开发依赖目录。`run.py` 优先使用 `lupa.luajit21`，若不可用则使用 `lupa.lua54`，并编译所有 Lua 文件。Python 只提供 JSON 编解码桥接和临时目录；在 Windows 上还用 `os.replace` 模拟目标 Linux 的原子覆盖重命名语义。所有测试数据位于临时目录，不读取设备或用户配置。

正式插件已有离线模拟覆盖字段解析、登录与会话校验、回答检查、评论不透明分页、临时 Cookie 交接、独立缓存、扫码 UI 状态、UI 取消/超时及摘要回退。桌面测试中的网络、KOReader 控件和子进程调度使用模拟模块；通过不代表网页端列表接口或 PW4 实机已验收。

另有 `tests/device_smoke.lua` 在设备 KOReader 目录内运行，参数为插件的绝对路径；它使用虚构 fixture、内存设置与离屏缓冲生成首页、回答列表、阅读页 PNG，不加载用户的知乎配置，不发起真实 API 请求。

API 核验记录见 [API_CONTRACT.md](API_CONTRACT.md)。
